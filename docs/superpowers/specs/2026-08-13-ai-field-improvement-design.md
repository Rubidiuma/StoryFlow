# AI 单字段完善设计

## 目标

在创建小说向导中帮助用户完善不完整的单个设定字段，同时保留用户控制权。系统不得静默改写输入，也不得同时修改其他字段。

## 不完整判定

字段去除空白和标点后：

- 没有中文、字母或数字时，判定为不完整。
- 有效内容少于 6 个字符时，提示内容可能过短。
- 达到 6 个字符时不主动提示，但用户仍可手动请求完善。

判定只用于界面提示，不会自动调用模型。

## 支持字段

题材、叙事结构、世界背景、主角描述、重要配角、文风、必须元素、禁止元素和结局倾向均提供“AI 完善”按钮。标题、选择频率和会话 ID 不支持 AI 完善。

## 交互

点击某字段的“AI 完善”后：

1. 前端提交目标字段名、当前字段原文和其他已填写设定。
2. 按钮进入忙碌状态，原输入保持可见且不被修改。
3. 后端返回一份简体中文建议。
4. 字段下方显示预览，并提供“采用”“重新生成”“取消”。
5. 只有“采用”会把建议写入当前字段；取消和失败均保留原文。

同一时间只允许一个字段生成建议。重新生成继续以当前输入为基础，不以上一次未采用建议为基础。

## API 与安全边界

新增 `POST /api/story-config/improve-field`。请求包含：

- `field`: 后端白名单中的字段名。
- `value`: 当前原文。
- `context`: 创建向导中其他允许字段的文本值。

后端按字段配置最大输出长度，拒绝未知字段、超长输入和非法上下文键。提示词要求：

- 只返回目标字段的建议正文，不返回 JSON、Markdown、解释或标签。
- 使用简体中文。
- 保留原意；信息不足时结合其他字段做保守补全。
- 遵守禁止元素，不引入明显冲突。

模型不可用返回 503；模型调用失败或输出无有效中英文字符返回 502。错误响应不包含模型原文、凭据或内部提示词。

## 前端结构

创建页为每个支持字段渲染统一的完善控件。`create.js` 负责不完整提示、请求、预览状态和采用/取消；现有三步校验与 6,000 字总限制继续生效。采用建议后重新运行字段和总长度校验。

## 测试

- 单元测试：有效字符统计、纯标点、短文本和完整文本判定。
- API 测试：字段白名单、上下文过滤、输出长度、中文提示词、模型不可用和非法响应。
- 页面测试：支持字段均有入口，标题和选择频率没有入口。
- 前端行为通过稳定的数据属性覆盖请求、预览、采用、重试和取消。

## 完成标准

- 用户可以只完善当前字段。
- 未点击“采用”时表单值绝不改变。
- 纯标点和短文本会得到明确提示。
- AI 失败不影响手工填写和正常提交。
- 全部新增与既有测试通过。
