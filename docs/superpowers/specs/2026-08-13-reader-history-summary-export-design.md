# 阅读器历史回退、剧情摘要与导出设计

## 背景与目标

StoryFlow 已经具备创建分支、保存记忆快照和导出 Markdown 的部分后端能力，但阅读器没有完整入口；滚动摘要服务也没有接入场景生成流程。本次改造要让普通用户能够在阅读器内发现并使用三项功能：从历史选择创建新路线、查看持续更新的剧情摘要、导出当前查看路线。

本次不删除或覆盖任何既有故事内容，不引入账号系统，不新增独立的故事管理页面。

## 用户体验

### 阅读器工具栏

阅读器头部提供两个始终可发现的操作：

- “剧情摘要”：展开或收起当前路线的摘要面板。
- “导出 Markdown”：下载当前正在查看的分支，而不是隐式下载故事记录中的当前分支。

工具栏沿用现有按钮、状态和响应式布局样式。操作失败时，在已有的阅读器错误区域显示中文提示。

### 历史回退与创建分支

阅读器在当前分支路径中查找已经完成选择的历史选择点，并在对应正文场景后显示所选行动及“从这里重新选择”按钮。

用户点击后：

1. 输入可选的分支名称；空值使用清晰的默认名称。
2. 前端调用分支创建接口。
3. 服务端保留原分支及其全部后续正文，从目标选择点复制当时的记忆快照，创建新分支并把故事当前分支切换到新分支。
4. 目标选择点在新分支上恢复为待选择状态，阅读器跳转到新分支并展示原有选项，用户可以选择不同路线或输入自定义行动。

“回退”在产品语义上始终表示无损分叉，不覆盖原路线。已有分支继续通过阅读器顶部的分支导航访问。

### 剧情摘要

每次成功提交场景后，以该场景的序号判断是否需要更新滚动摘要。第 5、10、15 个场景等正整数倍数触发一次摘要生成。

摘要更新是正文提交后的尽力而为操作：

- 读取当前分支最新记忆快照和最近一组场景。
- 调用现有滚动摘要提示词生成新的 `rolling_summary`。
- 成功时保存新的记忆快照；失败或模型返回非法数据时保留原快照，正文与选择状态不回滚。

阅读器摘要面板优先展示最新持久化的 `rolling_summary`。在尚未产生滚动摘要时，将当前分支各场景已有的短摘要按顺序组合成阶段摘要；没有任何场景时显示明确的空状态。摘要是对用户可见的剧情回顾，不展示隐藏选择效果、内部人物状态或提示词内容。

## 服务端设计

### 阅读器视图数据

Web 路由为阅读器构造以下附加数据：

- 当前分支路径上每个场景对应的历史选择点。
- 每个已选选择点的用户可见选择文本。
- 当前分支的用户可见摘要文本及其来源类型（滚动摘要或阶段摘要）。

模板只负责展示，选择文本解析和摘要回退逻辑放在独立、可测试的服务函数中。

### 分支接口

沿用 `POST /api/choices/{choice_id}/branch`，但把响应和仓储行为补齐为可直接进入新路线的语义：新分支拥有目标节点的历史状态，故事的 `current_branch_id` 指向新分支，并存在一个可供阅读器展示的待选选择点。

接口只允许对已完成选择且属于可访问故事的节点创建分支。找不到节点、节点尚未选择或状态冲突时返回稳定的中文可映射错误码。重复点击不会破坏原分支。

### 摘要编排

在场景事务提交成功后执行摘要编排。正文事务与摘要更新保持边界分离，确保摘要服务不可用时已经生成的正文仍然有效。

摘要快照沿用 `MemorySnapshot` 和仓储现有保存接口，不新增数据库表。触发规则继续由 `MemoryService.should_trigger_rolling_summary()` 统一定义。

### 按分支导出

扩展 `GET /api/stories/{story_id}/export.md`，接受可选的 `branch` 查询参数：

- 提供 `branch` 时，验证它属于当前故事并导出该分支路径。
- 未提供时，保持兼容，导出故事的 `current_branch_id`。

导出服务显式接收目标分支 ID，内容继续包括标题、故事设定、按顺序排列的正文和用户可见选择，不混入兄弟分支，也不导出隐藏效果。

## 前端设计

模板渲染历史选择记录、摘要面板和工具栏基础结构。`reader.js` 负责：

- 展开/收起摘要面板。
- 请求创建历史分支，显示进行中状态与错误，并在成功后跳转。
- 导出链接携带当前页面的 `data-branch-id`。

前端不在浏览器中重建剧情路径或摘要，避免与服务端状态不一致。所有新增按钮具备可读文本、键盘焦点样式和忙碌时禁用状态。

## 错误处理与一致性

- 摘要失败不改变故事最终状态，也不阻止下一场景生成。
- 分支创建失败时停留在原页面，不隐藏或修改原路线。
- 指定导出分支不存在或不属于故事时返回 404。
- 新分支创建与故事当前分支切换需要在同一仓储事务中完成，避免页面跳转到半成品分支。
- 页面只展示用户可见选择文字，不暴露 `effects`、模型上下文或内部记忆结构。

## 测试策略

### 单元测试

- 场景序号 5 的倍数触发摘要，其他序号不触发。
- 用户可见阶段摘要按场景顺序生成。
- 导出服务只遍历指定分支并包含该路径选择文字。

### 集成测试

- 第 5 个场景提交后保存更新过的滚动摘要。
- 摘要模型失败时场景仍成功提交且原快照保持有效。
- 从历史已选节点创建分支后，原分支不变、新分支成为当前分支并恢复待选择状态。
- 指定分支导出正确；跨故事分支返回 404；不传参数保持兼容。

### 页面与端到端测试

- 阅读器显示“剧情摘要”和“导出 Markdown”。
- 已选历史节点显示选择文本和“从这里重新选择”。
- 创建分支成功后跳转到新分支，并能看到待选选项。
- 多分支导航仍能返回原路线。

## 完成标准

- 三项功能均可从线上阅读器界面发现和使用，不需要手工拼接 API 地址。
- 回退不会删除或覆盖任何既有正文。
- 滚动摘要确实接入真实生成流程，并能在页面查看。
- 导出内容与当前查看分支一致。
- 新增测试和原有测试全部通过，静态检查无新增问题。
